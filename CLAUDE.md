Read this first in every session.

## What this is
Divvy is a Solana memecoin launchpad built on Raydium LaunchLab. Every coin trades against SOL and pays its holders an hourly dividend in a tokenized stock (NVDAx, SPYx and others). The full spec is in `HANDOFF.md`. The approved UI is **红利 hongli's premium green look** (owner, 2026-11-04: "premium hijau", clean like Pools without copying it: a dark page with a soft green glow, glass cards with hairline borders, one green button, green up, the round's pool as the hero). It is built as the app itself — `apps/web/src/app/globals.css` is the source of truth (a retheme of the earlier jinniu class system, so the components kept their class names; `prototype/jinniu-prototype.html` remains the structural reference). It replaced 金牛's clean white look (2026-11-03), which replaced design 牛 (2026-11-01), design A (红包) and the original dark green Divvy design; those prototypes are in git history (`git log --diff-filter=D -- prototype/`).

## Stack (do not change without the owner's OK)
- **Frontend:** Next.js 15 App Router (React 19) in `apps/web`. Upgraded from 14 with the owner's OK on 2026-10-26 (docs/AUDIT.md DEP-1).
- **API:** Fastify in `apps/api`.
- **Workers:** indexer, payouts and cron in `apps/worker`.
- **Data:** Prisma with PostgreSQL in `packages/db`, plus Redis.
- **Shared code:** `packages/shared` (types, anti-vamp, fee math) and `packages/solana` (LaunchLab, Jito, Jupiter, Helius).
- **Deploy:** Hostinger VPS with PM2 and Nginx.

## Hard rules
1. **Pixel-faithful to the approved look** (红利's premium green; `apps/web/src/app/globals.css` is the source of truth). A dark page with a soft green glow, glass cards with hairline borders, the centred nav pill, one green button, green sparklines, the floating dock on phones. The home was restructured away from the jinniu composition (owner, 2026-11-04: "mirip jinniu rubah dlu", then "dua panel"): a **two-panel band** (the round's pool with the hour line on the left, the next-payout countdown with the create actions on the right), the headline stats on a strip below, the **刚刚到账 ticker** (a running strip, not a card), then **live markets as a dense table** (`.ctable`/`.crow`) with a **featured/top-payers rail** beside it — the hero-split, bento and card grid are gone (`apps/web/src/components/board/Board.tsx`, `area-home.css`). Fonts: Inter Tight for Latin and numbers, Noto Sans SC for Chinese, Ma Shan Zheng for the brush 红 mark. Green up by default. If something looks wrong, ask; don't redesign. Every number is bound to real data; what there is no data for is left out.
2. **No invented on-chain facts.** Program IDs, mints, fee fields and SDK calls must be confirmed against the SDK source/IDL or on-chain data, and logged in `docs/VERIFIED.md` with the source.
3. **No mainnet spend** (PlatformConfig creation, funding wallets, test launches) without the owner's explicit approval in chat.
4. **Private keys** never go in the repo, the database, logs or client bundles. Hot wallets keep minimal balances with spend caps.
5. **The server is the authority** for anti-vamp, rate limits, amounts and fees. Client-side checks are only UI feedback.
6. **Mint addresses stay secret until the create lands.** Creates go only through Jito bundles. One exception (owner decision 2026-10-27): the creator's wallet, which signs and pays for its coin's create, sees it a few seconds early; the mint's signature never leaves the worker.
7. **The dividend engine is idempotent** (unique coin+hour) and has a dry-run mode. Run dry-run first.
8. **Copy:** sentence case, plain verbs, no all-caps labels. Keep the prototype's wording unless the owner changes it. "Paid every hour" becomes "credited every hour" only if the owner picks the claim model (HANDOFF §3.4).

## Conventions
- TypeScript strict everywhere. Use zod for API input validation.
- Amounts are integers in base units (lamports or token base units) and are serialized as strings.
- Every signed transaction is logged with its purpose and signature.
- Each phase ends with a short report: what's done, what was verified, what's blocked, and the next step.

## Commands
- `pnpm dev`: web (:3000), API (:4000) and worker in parallel. Reads the root `.env`.
- `pnpm db:migrate` (dev) / `pnpm db:deploy` (production): Prisma migrations in `packages/db`.
- `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`.
- Phase 0 scripts: `cd packages/solana && pnpm tsx scripts/phase0/<script>.ts` (see `docs/VERIFIED.md`). Anything that spends SOL needs `--send` and `I_HAVE_OWNER_APPROVAL=yes`.

## Where things live
- API contract (zod schemas for every §6 response): `packages/shared/src/api.ts`. The API's contract test fails on any extra or missing field.
- Anti-vamp: `packages/shared/src/antivamp.ts` and `imagehash.ts`. The API re-runs every check on launch.
- The mark in the app: `apps/web/src/components/Mark.tsx`. `Mark` is the 红利 mark (owner, 2026-11-04): the brush 红 in white on an emerald tile, drawn inline from the Ma Shan Zheng face (loaded in `layout.tsx`). `brand/hongli/src/mark.cjs` renders the same as the favicon (`icon.png`), the Apple icon, the PlatformConfig picture (`public/brand/hongli-mark-512.png`) and the site share images; `honglimark.ts` holds it as a PNG data URI for the coin share route (`og/coin/[mint]`). `Wordmark` is text: 红利 with a small "hongli". Don't edit the generated files by hand.
- Styles: `apps/web/src/app/globals.css` is the prototype's CSS verbatim (change both together). What the prototype doesn't draw is in `additions.css` (shared: real coin pictures and stock icons, modals, toasts, the wallet picker, admin) and one file per area: `area-home.css` (header, home, dock), `area-coin.css` (the coin page), `area-pages.css` (create, payouts, me, how, terms). The components use the prototype's class names; there's no mapping layer.
- Copy in both languages: `apps/web/src/i18n/msgs/` (one file per area, `defineMsgs(en, zh)`); English stays the prototype's wording.
- Coin pictures with no upload (demo coins, the create-page placeholder, the live fallback): `memeAvatarSvg(seed, name)` in `packages/shared/src/avatar.ts` — a real meme emoji chosen from the coin's name (Frog Lord → 🐸, Cash Cow → 🐮) on a tinted tile (owner, 2026-11-04: "logo meme beneran", replacing the old generated faces). The glyphs are Twemoji (Twitter/X, CC-BY 4.0) in `packages/shared/src/memes.ts` (generated; don't hand-edit). Real launched coins show the creator's uploaded picture. The mock API fingerprints the demo pictures from the same `memeAvatarSvg`, so change both together.
